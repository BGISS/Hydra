Adversarial Detector-Robustness Research

Hydra

// kill one signature, it grows a new head

A local, security-tuned LLM rewrites a benign, ransomware-shaped program in a closed loop, reacting to detector feedback each round. Hydra measures which detection survives an adaptive AI adversary — signature or behavior. The signature rule is evaded in one iteration; the behavioral rule is never evaded while the sample still behaves like ransomware.

⚠ Safety & ethics

  • Authorized, defensive research against Hydra's own lab detectors — never third-party defenses.
  • The sample is benign by construction: rewrites only throwaway files it creates, no network, no persistence, reverses itself on exit.
  • Mutated code runs only in a throwaway, network-isolated container.
  • Real malware is never executed. Everything runs offline; nothing leaves the machine.

How the loop works

seed sample (benign, ransomware-shaped)
  ↓
referee → arena (throwaway container: compile + run, no network)
  ├─→ YARA signature  → MATCH / CLEAN
  └─→ Falco behavioral (eBPF) → FIRED / SILENT
  ↓  verdict + reason: evade this, keep behavior
adversary (local LLM via Ollama) → rewritten source
  ↺  recompile · re-run · re-judge

The adversary sees each detector's verdict and reason and must reason about why it was caught — the adaptation step a template mutator cannot do.

YARA falls at iteration 1 and stays clean. Falco fires through every rewrite until iteration 9, where it goes silent only because the sample stopped performing the malicious behavior.

Why it matters

Field malware now uses LLMs to rewrite itself and reason about why it was detected (Google's PromptFlux/PromptLock, 2025). Hydra shows the consequence in a controlled lab: against an adaptive AI adversary, signatures are brittle and behavior is robust — because evading behavior requires abandoning the behavior.
